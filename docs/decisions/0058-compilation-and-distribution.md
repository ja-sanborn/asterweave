# ADR 0058 — Compilation, distribution and content protection

Status: Accepted

## Context

Asterweave requires a coherent first-party modular architecture, with independently usable gameplay execution and declarative game content.

## Decision

Tools own translation where applicable, coordinated validation, explicit build-time module selection and dependency resolution, compilation and packaging; Creator consumes those capabilities. Three independently useful, composable distribution targets are planned: a standalone compact JavaScript engine bundle (mandatory infrastructure, selected gameplay modules and dependencies), an encrypted game content package (canonical definitions and applicable assets), and a complete playable game (composed engine, encrypted content package, selected interaction modules and applicable presentation). The first two are Foundation deliverables; complete playable distributions follow applicable interaction and presentation integration. Physically exclude unnecessary executable modules, Creator and unrelated development tooling. Runtime loaders remain distinct from build Tools.

Permit safe dead-code elimination, minification, optional obfuscation and appropriate compression only where supported interfaces, selected capabilities, gameplay behavior and security invariants remain intact. Aggressive game-specific engine specialization is not required. Preserve the zero third-party npm dependency policy; exceptions require separate approval.

Distinguish required capabilities (necessary for correct operation), included capabilities (physically composed into the distribution), and used capabilities (actually exercised during play). Tools derive requirements from canonical data where reliable, accept justified explicit requirements and resolve dependencies before composition. Runtime consumers reject unsupported required configuration. Concrete requirement fields, dependency metadata and resolution algorithms require separate reviewed design; no manifest or discovery framework is implied.

Keep canonical JSON readable, unencrypted and independently supported. Build Tools always encrypt compiled game content packages; there is no unencrypted compiled package variant or encryption toggle. Complete playable distributions use encrypted game content packages. Authoring language files, Creator workspaces and standalone engine bundles do not require encryption. Packaging does not alter canonical source. Runtime loaders perform authenticated decryption and unpacking outside gameplay Engine; applicable consumers independently validate decoded canonical data before initialization. Direct JSON and decrypted package content must be semantically equivalent. Authenticated decryption neither establishes that decoded data is safe nor independently authenticates publisher identity. Preserve offline operation; no DRM, mandatory activation or external service, or confidentiality guarantee against the device operator. Embedded keys and decrypted data are recoverable. Compression and encoding are not encryption; obfuscation is reversible. Exclude credentials and unrelated private authoring material. Use established cryptographic primitives. Optional save-file encryption is separate.

Maintain independent engine, canonical definition, content, distribution and save version authorities. Compatibility requires explicitly supported formats, engine compatibility requirements and required capabilities. Compatible engine updates need not invalidate packages; pre-1.0 compatibility is not presumed. Reject unsupported formats, incompatible packages and unavailable required capabilities rather than silently dropping functionality. Successful authenticated decryption and applicable canonical validation precede initialization.

Tools verify applicable source validation, distribution integrity, dependency completeness, selected capability availability, public interface preservation, source-to-bundle behavioral equivalence, direct JSON versus decrypted package semantic equivalence, offline execution, exclusion of unnecessary modules and development tooling, and licensing compliance. Failed required checks prevent successful build completion. Verification is proportionate, not exhaustive gameplay certification. Preserve reproducibility where practical; secure encryption may produce different bytes across builds. Never weaken cryptographic security to obtain byte-identical artifacts; preserve behavioral reproducibility.

Preserve MPL-2.0 obligations for covered Asterweave software and applicable modifications. Independently authored games, assets and separate code may use their own licenses subject to applicable rights and obligations. Tools assist with required notices, creator attribution and applicable source availability information; distributors remain responsible. Compilation, minification, obfuscation and encryption do not remove licensing obligations or justify obstructing required notices or source availability. Review reference-game licensing individually. Concrete algorithms, keys, package structures, compatibility metadata, verification mechanisms, compilation and tooling interfaces require separate reviewed design. See [architecture](../ARCHITECTURE.md).

## Alternatives and consequences

Prefer explicit cohesive responsibilities and reviewed contracts over speculative generalized frameworks. Preserve applicable existing behavior, security and verification; accepted design does not establish implementation or authorize new feature scope.
